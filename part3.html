01・為什麼不用 Word

看得懂

數字、文獻、圖都從源頭自動接上

Word 最常出事的地方：改了一筆資料，內文、表格、摘要、圖要一處一處改，漏一處就前後不一致；文獻刪了一篇，編號要重排。
這條流程的做法：數字由分析程式寫出來，文獻由 Zotero 匯出，圖由腳本畫。改源頭，請 AI 重跑一次，全部一起更新。
Word 手工LaTeX＋AI 流程
改一筆資料內文、表、圖、摘要逐處改重跑一次，數字全部更新
引用文獻插入、重排編號，容易漏連到 Zotero；引了書目裡沒有的文獻，產生 PDF 時會停下來告訴你是哪篇
圖另外畫、貼上，字型跟內文不同gnuplot 腳本畫，圖上的字跟內文同一套字型
換期刊格式重新排版換期刊範本，內容不動
AI 幫忙複製貼上來回純文字，AI 讀得懂、改得動，改了什麼看得清楚
合作者只會 Word直接用另外出一份 Word 給他（只收 Word 的期刊也是）
說得出為什麼「改源頭、重跑一次」比逐處改 Word 可靠。

03・只要裝一次

裝得好

TeX、gnuplot、pandoc、Python 套件，請 AI 幫你裝

TeX Live 是什麼？要裝哪一個？

要把 LaTeX 編成 PDF，電腦裡要有一套「TeX 發行版」。最完整的一套叫 TeX Live，每年出一版；Mac 版的 TeX Live 叫 MacTeX。Windows 另有一套 MiKTeX，第一次裝比較小，缺什麼再自動補。我們在雲端實測、和 GitHub 自動編譯用的都是 TeX Live。三套都能用，範本不挑。

論文或文獻有中文（例如引了台灣的中文期刊），跟 AI 說「論文裡有中文，請改用 xelatex」就好，中文字型已經設好。

你的電腦是：
工具用途建議裝
TeX把 LaTeX 編成 PDFMiKTeX（比較小；要打開「缺套件時自動安裝」）。想一次裝齊也可以裝 TeX Live，但檔案很大
gnuplot畫圖gnuplot 官方安裝檔
uv（管 Python）統計分析uv：它會自己裝好 Python 和 numpy、pandas、scipy 等套件，放在範本資料夾裡，不動電腦原本的 Python
pandoc轉成 Word（需要時才裝）pandoc 官方安裝檔

請幫我裝寫論文要用的工具。每裝一個之前，先告訴我要裝什麼、從哪裡裝，我同意再裝；要我輸入電腦密碼時先停下來，我自己輸入。
1. TeX：用 winget 裝 MiKTeX（winget install -e --id MiKTeX.MiKTeX），裝好後把「缺套件時自動安裝」設成「是」（不要選每次問我），你在背景跑的時候才不會卡住。
2. gnuplot：用 winget 裝（winget install -e --id gnuplot.gnuplot）。裝好後打 gnuplot --version；如果找不到、或沒有印出版本就結束（winget 建的捷徑可能缺檔），請找出 gnuplot.exe 所在的 bin 資料夾，先告訴我你打算把它加進「使用者」的 PATH、會影響什麼，我同意再加；加完請我把 Codex／Claude 關掉重開，再打一次 gnuplot --version。

4. pandoc：winget install -e --id JohnMacFarlane.Pandoc。

05・Zotero

接得穩

文獻放 Zotero，書目檔自己更新

論文用的書目檔是 source/refs/refs.bib。三種接法，挑一種就好，第一種最穩：

A. 自動匯出推薦

  1. 把 Zotero 更新到最新版。到 Better BibTeX 官網下載 .xpi 檔（用 Firefox 下載要按右鍵另存），在 Zotero 選「工具 → 外掛（Tools → Plugins）」→ 齒輪 →「從檔案安裝（Install Plugin From File）」。
  2. 把這篇論文要用的文獻放進一個文獻集，例如「VP 論文」。
  3. 對文獻集按右鍵 →「匯出文獻集（Export Collection）」，格式選 Better BibTeX，勾「保持更新（Keep updated）」，存成範本裡的 source/refs/refs.bib（蓋掉範例那份）。
  4. 之後在 Zotero 加一篇，refs.bib 就自己更新。

B. 讓 AI 操作 Zotero

請 AI 幫你裝一個讓它能操作 Zotero 的小工具 zotero-mcp（要先裝 uv，再 uv tool install zotero-mcp-server），接到 Claude 或 Codex。之後 AI 能搜你的文獻庫。要讓它用 DOI 把文獻加進 Zotero，Zotero 要開著，而且要照 zotero-mcp 的說明另外授權。版本與設定以它的官方說明為準。適合熟一點之後再試。

C. 不裝外掛

Zotero 開著，跟 AI 說「請用 tools/zotero_export.py 把 Zotero 的『VP 論文』文獻集匯出成 source/refs/refs.bib」。

B 和 C 都要先在 Zotero：設定 → 進階，勾「允許此電腦上的其他應用程式與 Zotero 通訊（Allow other applications on this computer to communicate with Zotero）」。三種接法給每篇文獻取的引用代號（cite key）格式不一樣，中途換接法，請 AI 把 main.tex 的引用一起改。

沒有 DOI 的文獻（例如有些台灣的中文期刊）：在 Zotero 給那一篇加一個標籤 nodoi。產生 PDF 時就會放行，並列出來提醒你自己對一次書目。不要讓 AI 替它編 DOI。

工具的書目也會錯。這次範例用 Scite 查到 7 篇真文獻，它匯出的書目有兩個錯：把文章種類標成排版程式看不懂的寫法；作者名字裡的連字號（例如 Hsin-Feng）用了一個長得一樣、排版程式卻不認得的特殊符號。所以每篇都要用 DOI 打開原文對一次。

知道 refs.bib 從哪裡來，也知道工具匯出的書目要回原文核對。
06・數字與圖

畫得美

數字由程式寫，圖由 gnuplot 畫

論文裡沒有一個結果數字是手打的，圖也不是手畫的。原料放在 source/，程式和 gnuplot 照順序把它變成 output/ 裡的成品：

  1. 1資料 source/data/study_data.csv

    一列一個人，例如 dkas_t1 是第 12 週的知識分數。程式只讀，不改。

  2. 2分析程式 source/scripts/analyze.py

    算出平均、標準差、p 值、效果量，每個數字取一個代號；同時把表做成 .tex（給 PDF）和 .csv（給 Excel），把畫圖要的數字做成小表。

  3. 3成品 output/numbers.tex、tables/、figdata/

    例如 \newcommand{\DKASIntTOneMean}{37.04}：代號＝數字。

  4. 4畫圖腳本 source/gnuplot/*.gp

    讀 figdata/ 的小表，畫到 output/figures/。

  5. 5論文 source/paper/main.tex → output/main.pdf

    本文寫代號、放表放圖；排版時代號換成數字。

按下面的按鈕，模擬「事後發現有一位不符合收案條件、要排除」：同一句話裡的數字自己跟著變，你一個字都不用改。

main.tex 裡實際寫的是：At week 12, DKAS scores were \DKASIntTOneMean{} in the intervention group and \DKASCtlTOneMean{} in the control group (\DKASTOnePstat{}). For DKAS, $d$ was \DKASTOneD{} at week 12 and \DKASTTwoD{} at week 24.

兩組數字都是 10/22 實際跑範本得到的。數字會自動更新，句子的解讀不會：數字變了，用到它的句子要你重讀。

為什麼用 gnuplot？圖放大不會糊，圖上的字交給 LaTeX 排，所以字型、大小跟內文一致（技術上是用 cairolatex 輸出）。每張圖是一個小腳本，資料改了重跑就重畫；同一張小表，換一支腳本就能從折線圖變長條圖。你不用自己寫腳本，跟 AI 說要什麼圖就好（第 04 段第 7 步）。

# source/gnuplot/fig1_outcomes.gp（節錄，AI 寫的、build 會自動跑） set terminal cairolatex pdf size 12cm,6cm set datafile separator comma set xtics ('0' 0, '12' 1, '24' 2) plot 'figdata/fig1_dkas.csv' every ::1 using ($1-0.04):2:3 with yerrorlines ls 1, \ '' every ::1 using ($1+0.04):4:5 with yerrorlines ls 2
想一步一步做一次？打開練習頁：看原料、跑一次 build、追一個數字、排除一個人看全部一起變、把圖改成長條圖、加一個新表，六個練習加一個收尾，大約 30 分鐘，用的就是所長的論文。練習頁也放了一位老師照著貼、AI 真正回了什麼的實跑紀錄。練習頁第 07 段還有研究模擬：只給資料和文獻，AI 十步寫出一篇論文的實跑紀錄。
07・研究倫理

守得住

流程再快，這四件事還是你的

一

研究資料：四個條件都符合才放

去識別化；IRB 允許用每一家會碰到資料的 AI 工具，而且實際用的帳號、方案與設定符合核准條件（例如關掉「用我的資料改進模型」；不能只看是不是「學校／企業方案」）；資料管理計畫允許存放在 GitHub 這種境外雲端；儲存庫是 Private。Private 不等於可以放受試者資料。推上 GitHub 後，自動編譯也會在它的雲端機器上讀資料。有一條不確定，就先不要放。

二

每篇文獻都用 DOI 回原文

build 通過只代表「引用的文獻存在於書目檔」，不代表書目資訊正確，也不代表 AI 對它的描述正確。作者、年份、卷期，還是要用 DOI 回原文對一次。

三

結論說到多強，由你決定

AI 可以起草，但不能替你決定解讀。相關不寫成因果，效果不誇大，資料裡沒有的不寫。

四

照期刊規定聲明 AI 使用

多數期刊要求寫出用了哪個 AI 工具、用在哪裡、你怎麼把關，作者為內容負責。以你要投的期刊規定為準；範本已放了一段聲明可以改。聲明裡每一句都要是你真的做過的事：沒有逐篇對過文獻，就不要寫「每篇都核對過」。

四件事說得出來：資料四條件、DOI 回原文、結論自己定、聲明 AI 使用。
