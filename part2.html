01・一個資料夾＝一個小隊

看得懂

AI 換個對話就會忘；寫成檔案、開工先讀，就記得住

為什麼要一個資料夾？AI 的記憶各家分開，換一個對話常常就忘了。寫在資料夾裡的規則和紙條，哪一家打開都讀得到。
對研究的好處：每一步都留下檔案，事後查得到 AI 做了什麼、你改了什麼。
你（小隊長，人）
出題目、看成果、做決定
→
領隊（AI）
想清楚、寫紙條、驗收
→
隊員（AI）
照紙條動手、交成品；只有一家時由同一個 AI 兼

講師在 GitHub 上放了一份範本（已經建好的空白小隊），叫 ai-team-starter。第 02 段你會照它複製一份自己的，取名 my-research-team，再下載到電腦上。打開 my-research-team，會看到：

名字結尾有 / 的是資料夾，其他是檔案。.md 是純文字檔，用記事本就打得開。英文名字不用記，看中文說明就好。

你會看到的名字做什麼
AGENTS.md小隊公約：誰是誰、怎麼傳紙條、三種模式（第 03、04 段會講）、共同規則。Codex 讀這份。
CLAUDE.md只有一行 @AGENTS.md，意思是「去讀 AGENTS.md」。Claude 讀這份，所以兩家照的是同一份公約。
README.md這個範本的說明書，給人看的。
team.md這個小隊平常用哪一種模式。
roles/（角色）兩個檔：leader.md 是領隊，預設名字叫「洄瀾」（花蓮的舊名）；member.md 是隊員，預設叫「太魯閣」。名字和個性都可以改。
material/（材料）你的材料，公約規定 AI 只讀、不寫。練習用/ 裡放了一份虛構的照顧者訪談，給今天練習；換成自己的材料前先移走。
workspace/inbox/（工作區裡的紙條區）領隊寫的紙條（交辦工作的文字檔）：做什麼、什麼格式、怎樣算做完。裡面原本的 README.md 是說明，不是紙條。
workspace/outbox/（工作區裡的成品區）隊員交的成品。檔名最後有 -v1 是第一版、-v2 是第二版，每一版都留著。
workspace/log.md小隊紀錄：AI 每做完一步寫一行；領隊檢查了什麼、收下了哪一版，也寫在這裡。
.gitignore告訴 git 哪些暫存檔不要上傳，不用管它（Mac 上看不到是正常的）。
說得出領隊、隊員各做什麼，紙條和成品放在哪裡。
02・三步建好

拿得到

用範本建自己的私人儲存庫，下載到電腦上打開

先認識三個詞
  • 儲存庫：GitHub 上的一個資料夾（英文 repository，常簡稱 repo）。
  • 範本：講師放在 GitHub 上、已經建好的空白小隊，叫 ai-team-starter。你不改它，只照它複製一份自己的。
  • clone：把 GitHub 上那份資料夾下載到你的電腦。
這一段做完，你會有兩份一樣的 my-research-team：一份在 GitHub 上（Private），一份在電腦的 AI-workshop 裡。

  1. 2-1用範本建自己的私人儲存庫

    先用瀏覽器打開範本頁 github.com/cwstedctw/ai-team-starter，看得到一排檔案清單（AGENTS.md、material、workspace……）再往下做。範本網址打開是「404」（找不到頁面）時，先停下來回信問陳老師，不要讓 AI 自己建一個空的。

    方法一：在網頁上按。在範本頁按檔案清單上方的 Use this template → Create a new repository（找不到這個按鈕，也先停下來問陳老師，不要按 Fork）。名字那一格（Repository name）填 my-research-team；公開範圍（Public／Private）一定要選 Private（預設可能是 Public）；最後按 Create repository。

    方法二：請 AI 助手代勞。行前第 10 項裝好 gh（讓電腦記住你的 GitHub 登入的小程式）、登入過的人，在 AI 助手（第 6 項打開 AI-workshop 的那個）貼：

    請用 gh 從範本 cwstedctw/ai-team-starter 建一個私人儲存庫，名字叫 my-research-team，並 clone 到目前這個 AI-workshop 資料夾裡。做完告訴我三件事：clone 下來的完整路徑、GitHub 網址、它是不是 Private。

    AI 要連上 GitHub 時，會先請你核准，畫面上有一行英文指令。看得懂、是你剛請它做的事，就按同意（只同意這一次）：指令裡看得到 my-research-team、ai-team-starter 和 --private（私人），就是在用範本建你的私人儲存庫；只是查看的指令（例如 gh auth status，查有沒有登入）也算。看不懂，就按拒絕，拒絕不會弄壞東西；再問它「這一步要做什麼、為什麼要做」，或截圖問網頁版。

    Private 不等於可以放受試者資料，放之前先看你資料夾裡的 material/README.md（研究資料能不能放的四個條件）。

    完成判準：瀏覽器打開 github.com/你的帳號/my-research-team（方法二可以直接點 AI 給的網址），名字旁邊寫著 Private，下面的檔案清單看得到 AGENTS.md、material、workspace。只看到一大段英文說明、沒有檔案清單，表示範本沒複製到：先停下來回信問陳老師。

  2. 2-2下載到電腦上

    用方法二的人已經下載好了，不用貼下面這句，直接看最後的完成判準。用方法一的人，在 AI 助手貼：

    請把我 GitHub 上的 my-research-team 儲存庫 clone 到目前這個 AI-workshop 資料夾裡，做完告訴我完整路徑。
    完成判準：打開檔案總管（Mac：Finder），進行前第 6 項建的 AI-workshop，看得到 my-research-team 資料夾；點進去看得到 AGENTS.md（Windows 可能只顯示 AGENTS，也對）。

  3. 2-3在桌面版打開這個小隊

    開一段新的對話（不要接著用 2-2 那段），照行前準備第 6 項的方法，這次改選 my-research-team：

    • Codex：在輸入框上方點「選擇專案」→「新專案」；來源資料夾按「新增」，先進 AI-workshop，選 my-research-team、按「選擇資料夾」；專案名稱也打 my-research-team，再按「建立專案」。
    • Claude 的 Code：先在環境選單選「本機（Local）」，再選資料夾：先進 AI-workshop，選 my-research-team。

    要選 my-research-team 本身，不是外面的 AI-workshop，也不是裡面的 workspace。選錯了，AI 讀不到小隊的規則；報到時看路徑就知道對不對。

    打開後先說一句：

    請先讀 AGENTS.md，再跟我報到。
    完成判準兩樣：①它回話的第一行是「領隊 · 」接資料夾的完整路徑，例如 領隊 · D:\AI-workshop\my-research-team（Mac 像 領隊 · /Users/你的名字/AI-workshop/my-research-team）；路徑的最後一段要是 my-research-team。②輸入框旁的權限選單還是「要求核准」（Codex）或 Manual（Claude）。
    不是的話：第一行不是「領隊 ·」，或路徑最後一段不是 my-research-team，就關掉這個對話，照行前準備第 6 項重開 my-research-team。它說找不到 AGENTS.md，回 2-2 的完成判準，確認資料夾裡真的有。權限選單變了，照行前第 7 項改回來。

03・單人模式

跑得動

只有一家 AI，也能讓它先做、再換個角色檢查

單人模式由同一個 AI 輪流戴兩頂帽子：領隊的帽子、隊員的帽子。它每換一次帽子，就在資料夾裡留下紀錄：

  1. 領隊寫紙條放進 inbox：做什麼、什麼格式、怎樣算做完。
  2. 隊員做 v1（第一版）存進 outbox。第一行是交接：做了什麼、哪裡要小心、能不能直接用。
  3. 領隊驗收：成品引用的每一句原文，都回訪談稿找；查了哪幾句寫進 log.md。要改就寫退回紙條。
  4. 有退回才改 v2，另存新檔、v1 留著。最後向你回報。

貼這句試試（今天只用虛構的練習訪談）：

這次用單人模式。請把 material/練習用 裡的虛構訪談做初步編碼：列出 3 到 5 個主題，每個主題附一到兩句原文當證據，並標出你不確定的地方。

做的過程中，兩家不一樣：

  • Claude 的 Code（Manual）：改檔、跑指令前都會先問你，會跳好幾次權限視窗。這一步你請它做的事，就是在 workspace 裡建紙條、成品，或改 log.md；它也會查電腦現在幾點（視窗裡寫 date 或 Get-Date），用來寫檔名。
  • Codex（要求核准）：在這個資料夾裡會直接建檔、改檔，通常不會問你。
  • 跳出權限視窗時：看得懂、是你剛請它做的事，就按同意（只同意這一次）。看不懂，就按拒絕，拒絕不會弄壞東西；再問它「這一步要做什麼、為什麼要做」，或截圖問網頁版。不要選以後都不再問、或切換到自動模式的選項。

不管有沒有跳視窗，它說做完之後，都要打開檔案總管（Mac：Finder），進 AI-workshop → my-research-team，自己看這四個地方：

.md 是純文字檔。按兩下打不開的話：Windows 在檔案上按右鍵 → 開啟檔案 → 記事本；Mac 按住 control 再點檔案（觸控板可以兩指點一下）→ 打開檔案的應用程式 → 文字編輯（Mac 的選單字樣以你的畫面為準）。打開會看到 #、>、** 這些符號，是排版記號，不用管。

  • workspace → inbox 裡的紙條（檔名是日期和時間開頭的那張，例如 20261028-1430-訪談初步編碼.md；README.md 是說明，不是紙條）：有沒有寫清楚「怎樣算做完」？
  • workspace → outbox 裡的成品（檔名最後有 -v1）：第一行是不是交接？長這樣：「> 交接：做了什麼｜注意：……｜能不能直接用：……」。有退回紙條的話，-v2 改了什麼？
  • workspace → log.md：領隊有沒有寫它查了哪幾句、怎麼查？
  • 自己查兩句證據。成品裡的原文證據，格式像範本公約裡的這個例子：「我睡不好，白天上班就很恍神，有一次開車差點擦撞到前面的車。」（虛構訪談-X01.md 第 16 行）。只複製「」裡面的字，不要連「」和後面的括號。打開 material → 練習用 → 虛構訪談-X01.md，按 Ctrl＋F（Mac：Command＋F）貼上。找得到，就是真的原文；找不到，先看是不是多複製了括號或空白，還是找不到，就跟 AI 說是哪一句找不到，請它退回重做。不要用手打，全形標點很容易打錯。

AI 說做完，不等於做完。主題怎麼定、證據夠不夠，最後還是研究團隊決定；AI 給的是可以檢查的初稿。

接得上

兩家都有，就讓它們分工

先看你手上有什麼，下面會建議用哪一種模式（兩種接力怎麼做，寫在建議器下面）。

ChatGPT（Codex）
Claude
兩家的命令列工具（codex、claude）都裝好、登入了嗎？

命令列工具＝不開視窗、打一行字就能叫 AI 做事的版本。行前準備沒有裝；沒特別裝過，就選「沒有或不知道」。

手動接力：每一棒由你傳

  1. 兩個桌面版都照 2-3 打開 my-research-team：Codex 一個、Claude 的 Code 一個。
  2. 在當領隊的那一邊（例如 Claude），先說「這次用手動接力」，再說需求。它寫好紙條就會停下來，請你去叫隊員。
  3. 到另一邊（例如 Codex）說「你是隊員。看 inbox 最新的紙條，照著做。」它回話的第一行應該是「隊員 ·」。
  4. 隊員交進 outbox 就會停；你回領隊那邊說「收 outbox」，它會驗收、回報。

team.md 已經改成手動接力的，第 2 步可以不說。Claude 的 Code 要付費（Pro 以上）。每一棒都經過你，每一步都看得見。

自動接力：領隊自己叫隊員（講師示範）

  • 你只跟領隊說話，它會用另一家的命令列工具把隊員叫起來。
  • 開始前，領隊會先請你同意存一版（commit）。出了問題，可以請 AI 把檔案還原成存的那一版。
  • 每叫一次隊員，領隊會先請你核准。你同意的只是「叫隊員」這一下；之後隊員在資料夾裡建檔、改檔，都不會再問你。
  • 紙條、每一版照樣留在資料夾裡。

要兩家的命令列工具都裝好、登入，今天由講師示範。

自動接力時，領隊會執行下面這一行來叫隊員（寫在 AGENTS.md 裡，不用自己打）。權限視窗裡出現這一行，就是在叫隊員：

領隊是 Claude、隊員是 Codex： codex exec --sandbox workspace-write "你是隊員。先讀 AGENTS.md 和 roles/member.md，再照 workspace/inbox 最新那張紙條做。" 領隊是 Codex、隊員是 Claude： claude -p --permission-mode acceptEdits "你是隊員。先讀 AGENTS.md 和 roles/member.md，再照 workspace/inbox 最新那張紙條做。"
  • 英文不用懂，認得兩樣就好：開頭的 codex exec、claude -p＝叫另一家 AI 做一件事、做完就結束；引號裡那句＝交代給隊員的話。
  • 中間那段：--sandbox workspace-write 讓 Codex 只能寫這個資料夾；--permission-mode acceptEdits 讓 Claude 改檔不再問你，所以開始前要先存一版。

這四道檢查是領隊（AI）每一棒都要做的，因為指令「成功」不代表做對。你看它的回報有沒有交代這四件事；沒交代，就問它：

一

叫到的真的是隊員嗎？

隊員最後回覆的第一行要以「隊員 ·」開頭。看到「領隊 ·」，表示叫到第二個領隊，停下來告訴你。

二

outbox 真的多了新檔嗎？

指令正常結束，不等於做完。先看到新檔，才說隊員做好了。

三

叫隊員的指令結束了沒？

一棒可能要好幾分鐘。叫隊員的指令已經結束，就不能說「隊員還在做」。叫不起來就改單人模式，不要自己想別的辦法，也不要替隊員寫成品。

四

不該動的檔有沒有被動？

領隊執行 git status（請 git 列出：跟上次存的版本比，哪些檔案有變動）：變動只該在 workspace 裡。material、AGENTS.md、roles、team.md 有變動，就停下來告訴你。

知道自己適合哪一種模式，也說得出四道檢查。
05・跨電腦與遙控

到處用

辦公室開始、家裡接著做、手機看進度

辦公室電腦⇄GitHub（Private）⇄家裡電腦筆電

規則只有一條：開工先拉、做完就推。「拉」（pull）是把 GitHub 上的新版下載到這台電腦；「推」（push）是把這台電腦存好的版本送上 GitHub。

另一台電腦第一次用：先做完行前準備第 2～10 項，再照 2-2 下載（clone）一次，不用重新建儲存庫；打開的方法照 2-3。

開工時貼

開工前請先 git pull，告訴我從 GitHub 拿到了哪些新東西。

收工時貼

今天改了哪些檔案，請先列給我看，特別標出 material 裡新放的檔。我同意之後，再存一版並推上 GitHub。
