用所長團隊 2021 年發表的論文當例子，看一個數字、一張圖，怎麼從資料走進論文。看懂之後，照第 04 段做六個練習：你主要是跟 AI 說話（另外自己開幾次 Excel 看檔），工具裝好之後大約 30 分鐘。第 07 段是研究模擬：只給資料和文獻，看 AI 十步寫完一篇論文。

這頁會一直看到的詞（點一下可以收起來）
  • 原論文／範例論文：原論文是 2021 年發表在 BMC Geriatrics 的那篇；範例論文是範本裡用重建的練習資料重算、重寫的版本（output/main.pdf，9 頁），只拿來練習，不能投稿。
  • build：一個指令（uv run build.py），把資料算成數字、表、圖，再排成 PDF。你不用自己打，跟 AI 說「跑一次 build」就好。最後一行是 BUILD OK 就是成功，BUILD FAILED 就是停在某一步，它會說哪裡要改。
  • 代號：給一個數字取的英文名字。例如 DKASIntTOneMean 代表「介入組（Int）第 12 週（TOne）DKAS 的平均（Mean）」。論文裡寫代號，排版時換成數字；資料一改，數字跟著改。
  • CSV：Excel 打得開的表格檔，一列一筆、用逗號分欄。
  • LaTeX：學術論文常用的排版工具。你只要看它排出來的 PDF。
  • gnuplot：畫圖的程式，照一支小腳本（.gp 檔）把小表畫成圖。
  • DKAS／ADQ／SCIDS：範例研究的三個量表：失智症知識（DKAS，0–50 分）、失智症態度（ADQ，19–95 分）、失智照護能力感（SCIDS，17–68 分）。
  • p 值：假如兩組其實沒有差別，還會看到這麼大差距的機率。越小，越不像碰巧。
  • 效果量（Cohen's d）：兩組差多少，用「差了幾個標準差」來表示。大約 0.2 算小、0.5 算中、0.8 以上算大。
  • 存一版（commit）／推上去（push）：存一版＝在自己電腦記下資料夾這一刻的樣子，之後能回到這裡；推上去＝把存好的版本放到 GitHub。
  • Private（私人）：GitHub 上只有你和你邀請的人看得到。Private 不代表研究資料可以放上去（看主頁第 07 段的四個條件）。

01・一個數字的旅程

追得到

論文裡的 37.04，是從哪裡來的

用 Word 寫論文，數字是從統計軟體抄進去的。這條流程裡，論文沒有一個結果數字是手打的：程式算好、取一個名字（代號），論文裡只寫代號；等 build 把論文排成 PDF 時，才換成數字。下面跟著「介入組第 12 週的 DKAS 知識分數平均」走一次。

I048 是練習資料裡一位虛構居服員的編號，分數偏低。按下面的「排除 I048」，可以先看看練習 4 會發生什麼。

資料：
  1. 1
    source/data/study_data.csv原料

    一列一個人。真的檔案有 19 欄、用逗號分欄，這裡只挑 3 欄、用空白對齊方便看。dkas_t1 是第 12 週的 DKAS 知識分數（0–50 分；t0＝前測、t1＝第 12 週、t2＝第 24 週）。程式只讀這個檔，不改它。

    id group dkas_t1 I001 intervention 37 I002 intervention 44 I003 intervention 43 … I048 intervention 12 …（介入組共 70 人）
  2. 2
    source/scripts/analyze.py原料（程式）

    分析程式算介入組 dkas_t1 的平均，四捨五入到小數兩位，再給這個數字取名叫 DKASIntTOneMean（DKAS、介入組 Int、第 12 週 TOne、平均 Mean；代號裡不能有阿拉伯數字，所以 t1 寫成 TOne）。片段裡 # 後面的灰字是說明，程式不會執行。

    # 排除名單：老師決定，寫在程式最上面（第 33 行）。[] 是空的＝一個都不排除 EXCLUDE_IDS = [] …（中間省略一百多行）… # 下面兩行是「展開示意」：程式算到「DKAS、介入組、第 12 週」時做的事 s = grp["intervention"]["dkas_t1"] # 拿出介入組 70 人的 dkas_t1 分數，暫時叫它 s macros["DKASIntTOneMean"] = fmt(s.mean(), 2) # 等號左邊是名字：DKASIntTOneMean（macros 是放所有代號的清單） # 等號右邊是數字：s.mean() 算平均，fmt(…, 2) 四捨五入到小數 2 位 → 37.04 # 這一行的意思：把右邊算出來的數字，取名叫左邊的名字

    實際的 analyze.py 裡沒有這樣的兩行：3 個量表 × 2 組 × 3 個時間點，共 18 個平均，是同一段程式輪流算出來的，名字照「量表＋組別＋時間＋Mean」自動組起來。你不用自己打開 analyze.py：練習 3 問 AI，它會指出是哪一行（實跑時是第 211 行），那一行旁邊的中文註解就寫著 DKASIntTOneMean 這個例子。

  3. 3
    output/numbers.tex成品

    程式把每個數字寫成一行，格式是 \newcommand{\代號}{數字}：第一對大括號放名字（前面多一條反斜線 \），第二對放數字。所以第二行讀成「DKASIntTOneMean 代表 37.04」。這個檔每次跑 build 都會重新產生，不要手改。

    \newcommand{\NTotal}{140} \newcommand{\DKASIntTOneMean}{37.04} \newcommand{\DKASTOneD}{0.92}

    整個檔有 75 行這樣的代號，這裡挑 3 行：NTotal＝總人數；DKASIntTOneMean＝介入組第 12 週 DKAS 平均；DKASTOneD＝DKAS 第 12 週的效果量 d。

  4. 4
    source/paper/main.tex原料（論文本文）

    論文本文裡寫的是代號，不是數字：反斜線 \ 開頭、後面接 {} 的就是代號。這句有三個：\DKASIntTOneMean{}（介入組平均）、\DKASCtlTOneMean{}（對照組平均）、\DKASTOnePstat{}（p 值）。數字變了，這一句不用重打。

    At week 12, DKAS scores were \DKASIntTOneMean{} in the intervention group and \DKASCtlTOneMean{} in the control group (\DKASTOnePstat{})…
  5. 5
    output/main.pdf成品

    排成 PDF 時，LaTeX 把三個代號換成 numbers.tex 裡的數字。你看到的論文長這樣：

    At week 12, DKAS scores were 37.04 in the intervention group and 30.43 in the control group (p < 0.001)…

    中文意思：第 12 週時，DKAS 分數介入組平均是 37.04，對照組是 30.43（p < 0.001）。

按上面的「排除 I048」，看哪些數字一起變

  • 現在用的是全部 140 人，數字跟原論文對得上。

數字會自動更新，句子的解讀不會。例如排除一個人之後，摘要、Methods 和表 2 的說明裡「數字跟原論文相符」的說法就不再成立（練習 4 的 AI 會把這些句子列出來）：數字變了，用到它的句子要你重讀一次。

② 腳本 source/gnuplot/fig1_outcomes.gp：每一行在做什麼

set terminal cairolatex pdf size 12cm,6cm畫成 12 公分寬、6 公分高（12 公分是論文版面的寬度）。cairolatex 是一種存法：線條存成 PDF，圖上的字留給 LaTeX 排，所以跟內文同一套字型，放大也不會糊。
set output 'figures/fig1.tex'畫好存到 output/figures/：build 是在 output 資料夾裡叫 gnuplot 畫圖，所以腳本裡寫 figures/ 就是 output/figures/（下面的 figdata/ 也一樣）。會存成兩個檔：fig1.pdf 是線條，fig1.tex 是圖上的字。Word 版另外畫一份 PNG 圖片。
set datafile separator comma小表是 CSV，用逗號分欄。
set style line 1 lc rgb '#0072B2' lw 2 pt 7 ps 0.8第 1 種線＝介入組：lc 是顏色（#0072B2＝藍），lw 2 是線的粗細，pt 7 是點的形狀（實心圓），ps 0.8 是點的大小。
set style line 2 lc rgb '#D55E00' lw 2 pt 5 ps 0.8 dt 2第 2 種線＝對照組：橘色（#D55E00）、實心方塊，dt 2 是虛線。藍和橘是色盲也分得出來的配色。
set xtics ('0' 0, '12' 1, '24' 2)小表 time 欄的 0、1、2，在橫軸上標成 0、12、24（週）。
set autoscale y縱軸範圍跟著資料走。改圖之後，還是要打開 PDF 看點和誤差線有沒有被切掉。
set multiplot layout 1,31,3＝排成 1 列 3 欄：一張圖裡並排三張小圖 DKAS、ADQ、SCIDS（原檔這一行後面還有邊界設定，這裡省略）。
plot 'figdata/fig1_dkas.csv' every ::1 using ($1-0.04):2:3 with yerrorlines ls 1讀小表 fig1_dkas.csv；every ::1＝跳過第一列欄名。using 後面的數字是「第幾欄」：第 1 欄（time）稍微往左挪（-0.04）當橫軸位置，第 2 欄（平均）是點的高度，第 3 欄（標準差）畫成點上下的誤差線。ls 1＝用上面定好的第 1 種線（藍色）。
'' every ::1 using ($1+0.04):4:5 with yerrorlines ls 2'' ＝同一個檔。第 4、5 欄是對照組的平均和標準差，往右挪一點（+0.04），兩組的誤差線才不會疊在一起；ls 2＝第 2 種線（橘色虛線）。

這些你不用背，也不用自己寫：跟 AI 說要什麼圖，它會改腳本。檢查時看 PDF 的圖：點跟小表的數字對不對、有沒有被切掉。看懂這幾行，是讓你知道圖的顏色、大小、畫法都寫在這份檔裡，想改就跟 AI 說。

資料夾第一層還有：README.md（給你看的說明）、AGENTS.md／WORKFLOW.md（給 AI 看的規則和流程）、build.py（一個指令跑完整條流程）、material/（你的計畫書、投稿須知，AI 只讀）、workspace/（AI 的工作紀錄，想知道它做了什麼就看這裡）、tools/（小工具，AI 執行）。

為什麼要分開：原料是你的研究，要好好保存；成品隨時能重做，被改壞了只要再跑一次 build，所以成品不推上 GitHub。真的研究資料能不能交給 AI、能不能推上 GitHub，先照主頁第 07 段〈研究倫理〉的四個條件確認；Private 本身不代表可以上傳。

核對數字時，用 Excel 打開 output/tables 資料夾裡的 .csv 檔就好；看完關掉時按「不要儲存」。下次跑 build 之前要關掉，Excel 開著，build 會失敗。

想放一張自己在 Excel 做好的表

  1. 在 Excel 做表：第一列是欄名，下面一列一筆，不要合併儲存格。
  2. 「另存新檔」→ 存檔類型選「CSV UTF-8（逗號分隔）」，檔名用英文（例如 my_table.csv），存進 source/tables/（沒有這個資料夾就新建一個）。
  3. 跟 AI 說：「我在 source/tables/ 放了 my_table.csv，請把它放進論文的 Results，表標題寫＿＿，內文提到它，跑一次 build。」
  4. 你會看到：build 印出「my_table.csv → output/tables/my_table.tex」，最後一行 BUILD OK，PDF 多了這張表。表裡有中文，build 會停下來說要改用 xelatex，跟 AI 說「照 build 說的改」就好。要改內容：改 Excel、重存、再跑一次 build。

想用 Excel 的資料畫一張圖

  1. 在 Excel 做好資料：第一列是欄名（例如 month、intervention、control），下面一列一個點。
  2. 另存成「CSV UTF-8」，檔名用英文（例如 my_data.csv），存進 source/figdata/。
  3. 跟 AI 說：「我在 source/figdata/ 放了 my_data.csv，第一欄是＿＿、第二欄是＿＿。請照 WORKFLOW.md 第 4 步寫一支 gnuplot 腳本畫成＿＿圖，放進論文的 Results，跑一次 build。」
  4. 你會看到：source/gnuplot/ 多一支 .gp，PDF 多一張圖。打開 PDF 看：點和線沒有被切掉，數字跟你的 Excel 一樣。

表的數字是你手打進 Excel 的，不會跟著資料自動更新；程式算的表才會。2026-10-22 實測：照上面做，PDF 和 Word 版都有這張表和這張圖。

04・六個練習

動手做

你主要跟 AI 說話，大約 30 分鐘

開始前（回家自己做也照這張）
  1. 範本資料夾已經在電腦裡（資料夾名稱 ai-paper-kit）。還沒有的話，照第三部分主頁第 04 段第 1 步，從範本 github.com/cwstedctw/ai-paper-kit 建一份。已經照主頁第 04 段第 4 步開了自己的論文的：範例已經收進 examples/，練習的數字會對不上，先停下來回信問陳老師。
  2. 工具裝好了：照主頁第 03 段那句話請 AI 幫你裝，AI 列出四個版本號、沒有「找不到」才算。
